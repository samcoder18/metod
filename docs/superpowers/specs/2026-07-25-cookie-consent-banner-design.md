# Баннер cookie-согласия + страница политики конфиденциальности

Дата: 2026-07-25
Статус: утверждено пользователем (без ссылки на политику из футера)

## Цель

При первом визите показывать плашку «Сайт использует cookies и Яндекс.Метрику» с кнопкой «Понятно» и ссылкой на политику конфиденциальности. Выбор запоминается, плашка больше не показывается.

## Контекст и ограничения

- Статический сайт: `index.html`, 4 страницы блога (`blog/*/index.html`), `404.html`.
- Сборка: `scripts/build.mjs` копирует файлы из массива `templated` (корневые) и `blog/**/*.html` в `dist/`, подставляя `__SITE_URL__`.
- Яндекс.Метрика на сайте **не подключена** — счётчик не трогаем (решение пользователя). Баннер — только уведомление.
- Страницы политики нет — создаём.
- Палитра сайта (из `tailwind.config.js`): background `#100F0D`, raised `#1D1A16`, foreground `#ECE7DE`, secondary `#9C968C`, accent `#C9A24B`, border `#27231E`. Шрифт body — Onest.

## Решение (подход A)

### 1. `assets/cookie-consent.js` — новый файл

- Подключается одной строкой `<script src="/assets/cookie-consent.js" defer>` перед `</body>` на всех страницах: `index.html`, `blog/kak-ispravit-osanku/index.html`, `blog/mify-o-massazhe/index.html`, `blog/pochemu-bolit-spina/index.html`, `blog/stress-v-tele/index.html`, `404.html`.
  - На страницах блога путь абсолютный (`/assets/...`), как у остальных ассетов.
- Скрипт сам создаёт DOM плашки и инлайнит стили через `<style>` — зависимости от сборки Tailwind нет, `src/input.css` не трогаем.
- Внешний вид: плавающая плашка в левом нижнем углу; на мобильных (< 480px) — почти во всю ширину с отступами. Фон `raised`, текст `foreground`, рамка `border`, кнопка «Понятно» в `accent`. Появление — fade/slide-up, контент не блокируется.
- Текст: «Сайт использует cookies и Яндекс.Метрику для анализа посещаемости. Продолжая пользоваться сайтом, вы соглашаетесь с этим.» + ссылка «Политика конфиденциальности» → `/privacy.html` + кнопка «Понятно».

### 2. Логика показа

- При загрузке читаем `localStorage['cookie-consent']`. Есть значение → плашку не создаём.
- Нет → показываем; по клику «Понятно» записываем JSON с отметкой времени (`{v:1, ts:...}`) и плавно скрываем плашку.
- Если `localStorage` недоступен (try/catch) — плашка показывается при каждой загрузке, сайт не ломается.
- Клик по ссылке «Политика конфиденциальности» согласие **не** засчитывает — просто переход.

### 3. `privacy.html` — новый файл в корне

- В дизайне сайта: тот же `<head>` (шрифты, стили, favicon, meta), шапка и футер как у остальных страниц.
- Содержимое — типовая политика: оператор, какие данные собираются (cookies, Яндекс.Метрика), цели обработки, сроки хранения, права пользователя, контакты.
- Места для реквизитов (ФИО/название, адрес, email) — заметные плейсхолдеры вида `[УКАЗАТЬ ...]` для заполнения владельцем.
- SEO-поля (canonical, OG) используют плейсхолдер `__SITE_URL__`, как остальные страницы.

### 4. `scripts/build.mjs`

- В массив `templated` добавить `'privacy.html'` — файл попадёт в `dist/` с подстановкой `__SITE_URL__`.

### 5. Явно НЕ делаем

- Не подключаем и не меняем код Яндекс.Метрики.
- Не добавляем ссылку на политику в футеры страниц (по решению пользователя).
- Не блокируем контент до согласия, нет оверлея.
- Не трогаем `src/input.css` и Tailwind-сборку.

## Тестирование

Ручная проверка:

1. `node scripts/build.mjs --dev` — сборка проходит, `privacy.html` в `dist/`.
2. Открыть главную: плашка появляется в левом нижнем углу.
3. Нажать «Понятно», перезагрузить — плашки нет.
4. Очистить localStorage, открыть страницу блога — плашка появляется и там.
5. Ссылка ведёт на `privacy.html`, страница отображается в стиле сайта.
6. Мобильная ширина (DevTools) — плашка не ломает вёрстку, текст читается.
