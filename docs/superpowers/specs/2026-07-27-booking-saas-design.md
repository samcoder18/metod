# Интеллектуальная платформа записи для массажистов — дизайн

Дата: 2026-07-27
Статус: согласовано с заказчиком (секции 1–5 подтверждены в диалоге)

## 1. Цель и формат

SaaS-платформа для мастеров массажа: веб-приложение (PWA) для записи и ведения клиентов.
Мульти-тенантная (много мастеров), каждый мастер работает только со своими данными.

Пользователи:
- **Мастер** — кабинет с расписанием, заявками, карточками клиентов.
- **Клиент** — самозапись по публичной ссылке мастера, без регистрации.

Канал уведомлений — Telegram (единый бот платформы).

### Соответствие 152-ФЗ (обязательные требования, учтены в дизайне)

- Хостинг и БД — только на серверах в РФ (Timeweb Cloud / Yandex Cloud / Selectel; Docker Compose). Зарубежные PaaS (Render, Railway, Vercel) не используются (п.5 ст.18 152-ФЗ, ред. 2025).
- Согласие на обработку ПДн — отдельным документом (с 01.09.2025 нельзя встраивать в оферту): отдельный чекбокс на странице записи + политика конфиденциальности.
- Владелец платформы (ИП/ООО) подаёт уведомление в Роскомнадзор и вносится в реестр операторов ПДн (организационный шаг).
- Данные о здоровье (жалобы, противопоказания) — спецкатегория (ст. 10 152-ФЗ): отдельное согласие, шифрование полей в БД, доступ только у мастера-владельца.
- Telegram = трансграничная передача: в сообщениях бота минимум данных (имя, дата, время; без жалоб/диагнозов) + пункт про канал связи в согласии.
- ИИ-этап 2: мед. данные не передаются в зарубежные LLM; используются российские модели (GigaChat / YandexGPT) или анонимизация.

## 2. Архитектура (MVP)

Один репозиторий, четыре компонента:

- `backend/` — FastAPI (Python), REST API: авторизация, расписание, записи, клиенты. SQLAlchemy + Alembic.
- `frontend/` — React + Vite, PWA. Два интерфейса: кабинет мастера (после логина) и публичная страница записи `/:master_slug` (без логина).
- `worker/` — планировщик (APScheduler или Celery + Redis): раз в минуту проверяет очередь напоминаний и отправляет через Telegram Bot API. Один бот на платформу.
- PostgreSQL — единая БД. Мульти-тенантность через `master_id` во всех таблицах, изоляция на уровне запросов.

Деплой: один российский VPS/облако, Docker Compose (БД, бэкенд, воркер, статика фронтенда). Ориентировочно $5–10/мес на старте.

## 3. Модель данных (MVP)

- `masters` — мастер: slug для публичной ссылки, название практики, часовой пояс, настройки (длительность сеанса по умолчанию, перерыв).
- `services` — услуги мастера: название, длительность, цена.
- `working_hours` / `time_off` — недельное расписание и исключения (отпуск, праздники).
- `clients` — клиент: имя, телефон, telegram_id (после первого запуска бота), согласия (дата, тип, версия текста). Привязан к мастеру.
- `client_notes` — заметки мастера: текст, дата сеанса, флаги (противопоказания). Поля с жалобами шифруются (pgcrypto/Fernet).
- `bookings` — запись: клиент, услуга, дата-время, статус (`pending` → `confirmed` / `cancelled` / `done` / `no_show`), источник (самозапись / мастер).
- `reminders` — очередь напоминаний: booking_id, момент отправки (за 24 ч, за 2 ч), статус.

## 4. Основные потоки

- **Самозапись:** клиент открывает `/:master_slug` → выбирает услугу → свободные слоты (working_hours минус занятое, с перерывами) → имя + телефон + отдельный чекбокс согласия на ПДн → экран «Заявка отправлена». Запись создаётся со статусом `pending`.
- **Подключение Telegram:** на экране подтверждения — кнопка «Получать напоминания в Telegram» (deep-link на бота с токеном записи). Start привязывает telegram_id к клиенту. Если не подключил — мастер видит и напоминает лично.
- **Подтверждение мастером:** мастеру в бота приходит «Новая заявка: завтра 15:00, Анна, массаж спины» + кнопки «Подтвердить / Отклонить». При подтверждении клиенту уходит сообщение. Записи, внесённые мастером, подтверждения не требуют.
- **Напоминания:** воркер ежеминутно отправляет созревшие reminders: за 24 ч (с кнопкой «Отменить») и за 2 ч. Отмена клиентом → статус `cancelled` + уведомление мастеру.
- **Кабинет мастера:** календарь (день/неделя), список заявок, карточка клиента (история посещений + заметки), «Завершить сеанс» с полем заметки, отметка `no_show`.
- **Регистрация мастера:** email + пароль, онбординг в 3 шага: профиль и slug → услуги → расписание. После этого публичная ссылка активна.

## 5. Безопасность, ошибки, тестирование

- **Авторизация:** JWT (access + refresh), пароли — bcrypt. Клиентам логин не нужен: управление записью — по ссылке с токеном и через бота.
- **Изоляция тенантов:** master_id только из JWT; middleware не принимает чужой id. Обязательный тест на утечку между тенантами.
- **Антиспам на публичной записи:** rate-limit по IP и телефону, honeypot-поле.
- **Надёжность:** при недоступности Telegram API — повторы с backoff (3 попытки), затем пометка ошибки и сигнал мастеру. Двойное бронирование слота исключено уникальным ограничением в БД. Все даты в UTC, отображение — в часовом поясе мастера.
- **Бэкапы:** ежедневный `pg_dump` в объектное хранилище в РФ, хранение 30 дней.
- **Тесты:** бэкенд — pytest (юнит: расчёт слотов, переходы статусов; интеграционные: API на тестовой БД); фронтенд — Vitest; e2e «клиент записался → мастер подтвердил → напоминание ушло» — Playwright на тестовом стенде.

## 6. Этап 2 — ИИ-функции (после обкатки MVP)

- **Голосовые заметки → записи:** мастер надиктовывает после сеанса; Yandex SpeechKit (серверы в РФ) → текст; LLM структурирует (жалобы / что делали / реакция / рекомендации); мастер проверяет и сохраняет.
- **ИИ-подсказки по возврату:** еженедельно находит клиентов, давно не приходивших (>45 дней), готовит персональный текст приглашения; отправка через бота по кнопке мастера. В LLM-запрос — только имя и факт давности, без мед. деталей.
- **ИИ-чат на сайте:** виджет на публичной странице отвечает на вопросы из базы знаний мастера (заполняется в кабинете) и ведёт к записи. Без ПДн до момента записи.

## 7. Дорожная карта

1. MVP (разделы 2–5).
2. Пилот на первом мастере (заказчик), 2–4 недели обкатки.
3. Этап 2 по приоритету: голосовые заметки → возврат клиентов → ИИ-чат.

## Исходные решения (итог брейншторма)

- Формат: веб-приложение (PWA), SaaS для многих мастеров.
- Пользователи: мастер + самозапись клиентов с подтверждением мастером.
- Стек: FastAPI + React (выбор заказчика из трёх предложенных подходов).
- Уведомления: Telegram.
- MVP: расписание, самозапись, Telegram-напоминания, карточки клиентов. ИИ — вторым этапом.
